# I-26 Connector 3D drive-through: source

Builds `i26-connector-3d.html`, a single self-contained page (about 32 MB) that shows the completed I-26 Connector (NCDOT I-2513, Asheville) in 3D, with 12 drive-through routes, traffic, four camera modes and place labels. Everything below is what it takes to regenerate or change that file.

## What it is built with
- **Python 3.13 pipeline (`py/`)** managed with [uv](https://docs.astral.sh/uv/) (`pyproject.toml`, `.python-version`) turns the NCDOT plans and public data into road geometry, terrain and scenery. Libraries: numpy, scipy, shapely, pyproj, rasterio, matplotlib, pymupdf (reads the plan PDFs), `triangle` (meshing), pyarrow (Overture data). Pinned in `pyproject.toml`.
- **three.js r160 viewer (`web/src/`)**, plain JavaScript with no bundler. `web/build.py` inlines three.js, the scripts, the binary scene buffers and the images into one HTML file, so the result needs no server and no internet.
- **Playwright + headless Chromium (`web/shot.js`, `web/play.js`)** for test screenshots and a check that all 12 routes play to the end. Optional.

## Layout
| Path | Contents |
|---|---|
| `py/` | pipeline scripts (order below) |
| `web/src/` | viewer: `core.js` (sky, terrain, roads, bridges), `scenery.js` (buildings, storefronts, trees), `drive.js` (routes, traffic, cameras), `ui.js` (panel, HUD, labels), `style.css`, `index.html` |
| `web/build.py` | inlines everything into `i26-connector-3d.html` |
| `work/` | cached inputs and intermediates (about 280 MB, see below) |
| `run_all.py` | rebuild from `work/` (`uv run python run_all.py`; `run_all.sh` is a wrapper); also refreshes `serve/index.html` when a local `serve/` folder exists |
| `tools/fetch_imagery.py` | downloads the aerial GeoTIFFs into `work/maxar` (about 524 MB) |

Paths are relative, so the folder can live anywhere. Set `I26_WORK=/path` to use a different data folder.

## Pipeline (run in this order, from `py/`)
1. **Plans to geometry (done once; results cached in `work/`):** `parse.py`, `pdfdraw.py`, `georef*.py` (registers the plan sheets to NC State Plane metres, EPSG:32119), `sheets.py` (pavement and bridge polygons), `align*.py` (alignments), `decks.py`, `arrows.py`.
2. **Public data (done once):** `dem.py` (elevation tiles to `dem_sp5.npy`), `overture.py` (roads, buildings, places, water into `work/ov`), `imagery.py` and `mosaic.py` (aerial base map and the three 0.6 m texture atlases).
3. **Rebuild steps (`run_all.sh`):** `profiles2.py` estimates road heights and adds bridges; `meshz.py` assigns pavement mesh heights and under-bridge clearance (`caps.py`); `walks.py` lays the plans' sidewalks (red) and multi-use paths (purple) at curb height; `terrain.py` grades the ground to roads and walks; `routes.py`; `marks.py` (US marking roles from `paint.py`: yellow left edges, white right edges, dashed lane lines, double yellow centre lines); `scenery.py`; `export.py`; `web/build.py`.

Coordinates: the scene is State Plane metres with X = x - 285000, Y = elevation, Z = -(y - 210000).

## Inputs and where they come from
- **Plans (supplied in the project folder, not duplicated here):** `I2513_I26_Connector.kmz` (2018 design, all sections) and `ashevillei-26-connector-map-1/2/3.pdf` (newer Section B/D maps). `work/pdf*.pkl`, `work/pdf_layers.pkl` and `work/kmz*` are their parsed forms.
- **Elevation:** AWS terrarium tiles (`s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`), cached in `work/dem`.
- **Roads, buildings, places, water:** Overture Maps release 2026-10-21.0, cached in `work/ov` (`overture.py` re-fetches it).
- **Aerial imagery:** Maxar Open Data, Hurricane Helene event, pre-event scene 2019-11-09 (`events/HurricaneHelene-Oct24/ard/17/<quadkey>/2019-11-09/103001009D337C00-visual.tif`, CC BY-NC 4.0, attribution required). The 524 MB GeoTIFFs are not in git; `python tools/fetch_imagery.py` downloads exactly the 12 files the model was built with (sizes are checked). The processed result is already in `work/scene` (`base.jpg`, `atlas0-2.jpg`); run `py/imagery.py` only to re-cut it.

## What `work/` holds
`pdf*.pkl`, `kmz_sp.pkl`, `sheets_plan*.pkl`, `pieces.pkl`, `align_*.pkl`, `struct_merged.pkl`: parsed plan geometry. `profiles.pkl`: road heights. `mesh.pkl`: pavement meshes. `walks.pkl`: sidewalks and paths. `marks.pkl`, `routes.pkl`, `scenery.pkl`: markings, drive paths, buildings and trees. `terrain_tiles.npz`: graded terrain. `scene/`: image atlases (the binary scene files are regenerated by `export.py`). Two large derived files (`terrain_conf.npy`, `road_dist.npy`) are left out and regenerated by `terrain.py` in seconds.

Verified: from this folder, `terrain.py`, `export.py` and `web/build.py` reproduce the delivered HTML byte for byte.

## Known approximations
- Road heights and grades are estimates (terrain plus bridge clearances); the plans contain no vertical profiles.
- Section B uses the newer public-meeting PDFs; the I-40 end uses the 2018 KMZ, which has no lane lines, so those lanes are synthesized.
- Beyond the plan limits (I-240 east, Patton Ave into downtown and West Asheville, US 19/23 north) roads are simplified Overture centrelines.
- Imagery is pre-construction (Nov 2019); storefront facades and signs are generated from Overture place names, not photos.
- Bridges are the only things that cast shadows. The viewer works them out at load time from the deck surfaces (`buildUnderShade` in `core.js`): ground, roads, lower decks, piers and cars are darkened straight under a deck (`US_K.x`) and in its shadow from the scene's fixed sun (`US_K.y`). Each deck has a flat underside 1.7 m below its surface, in a darker grey.
- Hand-tuned spots: `BRIDGE_REACH` in `profiles2.py` (Brevard Road bridge spans the southern collector too), `RIDE` in `profiles2.py` (which road rides which bridge), and the landmark label list in `export.py`.

## Testing
`node web/shot.js out.html '[{"cam":[x,y,elev,tx,ty,elev],"out":"a.png"}]' 1200 750` renders views in headless Chromium (about a minute each on software GL). `node web/play.js out.html` starts every route and checks it reaches the end with no console errors.

## Setup
```
uv sync                                  # Python 3.13 and packages
uv run python tools/fetch_imagery.py     # aerial tiles (once)
uv run python run_all.py                 # rebuild i26-connector-3d.html
```
The `work/` data folder is not in git (about 380 MB); it is shared in the project folder.

## Working together
Edits to the viewer (`web/src`) need only `python3 web/build.py` (after `export.py` has produced `work/scene` buffers). Edits to heights, bridges or grading start at `profiles2.py` and run through `run_all.sh`. `work/` and the built HTML are git-ignored; share `work/` through the project folder, a shared drive or Git LFS.

## Publishing
The source lives at https://github.com/wxtrails/i-26-connector-model (branch `main`). The built model is served by GitHub Pages from the `gh-pages` branch at https://wxtrails.github.io/i-26-connector-model/. That branch holds only `index.html` (the built `i26-connector-3d.html`) and an empty `.nojekyll`; the HTML is never committed to `main`.

To publish a new build after `uv run python run_all.py`:
```
git fetch origin gh-pages
git worktree add ../pages-tmp gh-pages
cp i26-connector-3d.html ../pages-tmp/index.html
git -C ../pages-tmp commit -am "Publish model"
git -C ../pages-tmp push origin gh-pages
git worktree remove ../pages-tmp
```
Pages is set to deploy from branch `gh-pages`, folder `/` (Settings > Pages). The site updates a minute or two after the push.
